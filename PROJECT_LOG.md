## Lecciones aprendidas

- [2026-10-09] `geo.volumen` con la integración de OpenCascade sin tolerancia puede errar mucho en superficies libres muy recortadas (+45 % en un cuerpo de un .f3d); con tolerancia tarda 27 s. Control: malla relativa (~0,3 s) y, si difiere más de 5 %, malla fina. La malla necesita ángulo 0,2 rad (más fino: 7–17 s) y desvío ≥ 0,01 mm (menos, una cara B-spline no se malla). · Evidencia: `tests/test_abrir_externo.py::test_volumen_y_area_en_forma_libre`, bobina de 1 mm de `test_solidos_crear.py`.
- [2026-10-09] Desde la consola Bash del agente, una barra invertida seguida de n o r (\n, \r) escrita en un heredoc llega como salto de línea REAL al archivo (rompió `ventana.py`, un test, `intercambio.py` y esta misma lección): para escribir esas secuencias en código usar el editor o armar la barra con `bytes([92])`. · Evidencia: SyntaxError «unterminated string literal» tres veces.
- [2026-10-09] OpenCascade guarda la malla en la forma y reusa una más fina aunque se pida más gruesa: para bajar el detalle hay que limpiarla (`geo.teselar(..., rehacer=True)`). · Evidencia: cilindro 88 → 396 → 396 triángulos; `test_rehacer_respeta_un_detalle_mas_grueso`.

- [2026-10-09] En la prueba de humo, para que un widget «vea» el ratón usar un evento simulado (`_mover`), no `QTest.mouseMove`: este mueve el cursor real y falla si la persona usa el ratón. · Evidencia: «Entrada dinámica» 3/5 fallas antes, 2/2 OK después.
